# first vps verification

status: passed on one Debian 13 VPS. raw terminal captures stay local; this note
is redacted.

## target

- Debian 13 (trixie), amd64, systemd.
- `ssh.socket` disabled and inactive, `ssh.service` enabled and active. this
  host exercised service mode, not socket mode.
- repo commit `7396621`, config kept out of git. password generated on the host,
  rotated manually, generated file removed.
- staged run: dry-run, access, default-account disable, decoy, then the rest.

## stages

1. dry-run planned the new user, key, generated password, `nftables` ruleset with
   `1/tcp`, and the ssh drop-in. `--keep-default-users --keep-root-password` left
   `debian` and the root password untouched.
2. phase 1 created the user and key, moved ssh to `1/tcp`, wrote key-only auth
   and `AllowUsers`, and applied an input-drop ruleset with `tcp dport 1 accept`.
   the first attempt stopped on a transient dpkg lock after the users module,
   before firewall or ssh changed anything. a rerun after the lock cleared
   completed the phase. the host was never locked out.
3. phase 2 set `debian` to `/usr/sbin/nologin`, kept its password at `L`, expired
   the account, removed it from sudo/docker, scrubbed the cloud-init sudoers
   grant and added `DenyUsers debian`. key login as `debian` was denied and
   password authentication was refused.
4. phase 3 installed the decoy on `22/tcp`, delivered the banner, refused auth,
   and started fail2ban with the sshd jail on port `1`.
5. phase 4 installed the remaining tools, zsh, docker, python and updates. the
   first full audit reported `95 ok, 6 warn, 0 fail, 3 skip`. after a reboot the
   audit reported `96 ok, 5 warn, 0 fail, 3 skip` and no pending reboot.

## warnings reviewed

- `NEW_USER` in the docker group: intentional, docker is root-equivalent.
- no generated password file: the password was rotated and the file removed.
- `dnsutils` missing: trixie installs `bind9-dnsutils`; the audit check was
  corrected.
- cloudflared still running while the module is disabled: it was not installed
  by this run. inspect it and either stop it or configure the module and token.
- five world-facing listeners: `1/tcp` is real ssh, `22/tcp` is the decoy, and
  `5355` is systemd-resolved LLMNR. the nftables input policy drops everything
  except `1` and `22`, so `5355` is not reachable through the host firewall.

## not proven here

- one host only. the other VPS were not touched.
- socket-activated ssh was not exercised; this host used `ssh.service`.
- cloudflared was not tested with a real dashboard token.
- fail2ban was not made to ban an external source on purpose.
- provider firewall configuration is external and was changed manually.
- raw phase captures and screenshots remain local and unredacted.
